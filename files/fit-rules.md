# Fit rules

How to judge whether a job fits the user. Use these rules in step 9 of SKILL.md, for every job that survived steps 3 to 8.

**Do not use this file to decide place or years of experience.** The Decisions section in SKILL.md handles those first. Where this file and SKILL.md differ, SKILL.md wins.

## Evidence about the user

Read `files/profile.md` (or the files in `data/`, if the user keeps their CV evidence there). The languages and their levels are in `files/preferences.md`.

Credit only what is written in these files. Coursework or "learning" is not the same as experience.

## 1. Hard filters (before judging fit)

- **Language level:** check only the languages the posting names as *required*. Compare the level the posting asks for with the user's level in `files/preferences.md`. A required level that isn't stated counts as fluent. Fail if the user's level is below what is required. For example: if the posting requires fluent French and the user's French is conversational, the job fails.
- **Seniority:** acceptable = the levels in `files/preferences.md`, judged by what the posting asks for, not only the title (an "Associate Consultant" can be entry level). Not acceptable = clearly above or below those levels, or the years limit in `files/preferences.md`.
- If either filter fails, the verdict is **skip** and you stop there.

## 2. Judging fit

Be honest, not encouraging: a false "apply" wastes the user's time.

Apply these in order:

1. **Find the must-haves:** what the posting treats as essential (years, specific tools, domain experience, seniority, language, location). Separate them from nice-to-haves.
2. **Check each must-have against the evidence files.** Mark it met only if a file shows it.
3. **apply** only if the user meets every must-have, OR misses at most one AND has an unusually strong strength that the posting explicitly values.
4. **skip** if any of these hold:
   - the user misses two or more must-haves;
   - any single must-have is a hard blocker (wrong seniority, wrong domain, required years far beyond the user's, a required tool or domain completely absent);
   - the role's core function is something the user has no evidence of doing.
5. **borderline** only if you can name specific open questions whose answers would flip it between apply and skip. Never use borderline as a hedge.
6. **Seniority check:** if the role expects the user to advise, lead or out-level people more senior than they are, count that as a missed must-have.

## 3. What to write down for each job

- **verdict:** apply / borderline / skip
- **confidence:** high / medium / low (then apply the confidence rules in SKILL.md Decisions)
- **strengths:** 2 to 5 concrete matches, each naming the posting requirement and the line in the user's files that meets it
- **gaps:** 0 to 5 requirements not covered by the user's files
- **open questions:** empty for a clear apply or skip, required for borderline
- **reason:** one or two sentences, especially for a skip
